# 逐帧拉片

选择或连接一路视频，手动开始后检测切点，按需输出关键帧、H.264/AAC镜头片段和原始音轨。结果保存为工作区文件、JSON清单和独立素材节点组；不会自动调用模型。

## 本地检测

本地检测无需 Python、视觉模型或模型 API。每个解码帧按真实时间戳分析，最长边缩到 256 像素，不降低帧率。“逐帧”指检测遍历全部解码帧，关键帧输出仍为每镜头一张。

检测分值由 **75% 的 RGB 空间差异 + 25% 的平滑色彩直方图差异**组成，范围为 0～100，是本检测器自己的量纲。

- **Adaptive**：以近 1.2 秒变化分值的中位数估计运动背景，最多保留 180 帧；触发阈值为 `max(4, 中位数) × 切镜阈值`，默认切镜阈值为 3。
- **Content**：直接使用绝对变化分值，默认阈值为 27。
- **最短镜头**：默认 0.6 秒。候选切点需形成局部峰值，间距不足时保留更强候选；短暂回到原画面的闪帧会被抑制，不足最小时长的尾段并入前一镜头。

调低阈值可增加切点，调高可减少切点；没有切点时整段视频作为一个镜头。检测主要针对画面变化，不保证覆盖渐变转场或语义变化，也不承诺与其他检测器结果一致。

解码使用临时 RGB 分块，处理后删除。内存保留当前所需帧、分块和时间戳；解码快于分析时，临时磁盘占用可能增长。视频切割会重编码，耗时与原视频分辨率、时长和镜头数量有关。

## 宿主辅助分析

默认关闭。开启后，本地结果先保存，再将原始视频、关键帧、结果清单与最多2000字分析重点交给当前宿主Agent。宿主负责逐镜头观察、运动与叙事分析，并通过画布工具保存完整正文报告。无需配置平台语言模型。委托状态与实际产物完成分开报告，宿主失败或取消保留本地结果；分析质量与费用由宿主能力决定。

## 文件与任务边界

每次处理固定工作区与视频路径。输入变化时保留已有结果，不覆盖当前分析。成功产物保留供撤销与引用；取消失败或尚未确认任务终止时保留本次目录，并阻止历史修改和删除节点，避免写入中的文件被移除。

## 安装与构建

在仓库根目录执行现有的typecheck与build命令，或统一运行`bun run build:nodes`。默认产物为`build/nodes/frameAnalysisNode/`中的React ESM、样式、manifest和install.json。依赖Go提供FFmpeg fluent接口和工作区文件能力，对应输出需启用图片、视频、音频节点插件；不需要Python。
