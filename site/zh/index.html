你的 Agent。你的画布。你的影片。

本机运行的视频创作工作台，由你的 Agent 操作。Codex、Claude Code 或任何 MCP Agent 负责规划，OpenCinema 为它提供节点画布、图像与视频工具、3D 预演、审片和最终剪辑，而每一个镜头都由你拍板。

工作方式

指挥。看见。完成。

  1. 01

    指挥

    选中一个节点、一组镜头，或者什么都不选。在底部输入里描述要改什么。范围由你划定。

  2. 02

    看见

    Agent 操作的就是你眼前这张画布。打开编辑台、画一块选区、换一条参考、保留一个满意的版本。

  3. 03

    完成

    按六项检查审阅每个候选。只替换出问题的那一镜。连同音轨渲染完整成片。

功能

一张画布，从想法到成片。

画布

每一份素材、每一个步骤，都是节点。

分镜、图片、片段、音频、预演、生成、审片和剪辑计划都在一张画布上，连线就是参考关系。内置 13 个节点插件，从文本与媒体到分析与生成，外加一个协作扩展。

  • 拖入文件即生成节点
  • 分组、整理、批量连线、撤销
  • Agent 的每一步都是看得见的状态变化

范围

Agent 能动什么，由你决定。

底部输入只作用于你的选择：一个节点、框选的一组节点，或整张画布。生成节点可以在「生成」和「让 Agent 调整节点本身」之间切换。参考带序号，你知道模型会收到什么。

  • 一个节点、N 个节点，或整张画布
  • 参考显示为带序号的标签
  • 手工与 Agent 共用同一条撤销历史

编辑台

只改需要改的地方。

画一块选区，就只有这块区域会变。裁剪变换、宫格切分、重新打光、换机位、拍全景。截取片段、提取音轨、分离音视频、变速、转写，全部通过本机 FFmpeg 完成。

  • 图片：局部重绘、裁剪、宫格、打光、机位、全景
  • 视频：截取、取帧、音频、变速、逐帧拉片
  • 结果成为新节点，原素材不动

预演

先看清镜头，再去生成。

在白模舞台上编排走位与相机。按镜头导出 RGB、深度与法线层，固定为生成用的参考节点。预演与深度是构图和节奏的参考，不是运动锁定。

  • 人物、布景、相机走位、Take
  • 每镜导出 RGB、深度、法线
  • 对真实素材做逐帧拉片、姿态追踪与相对深度

你的模型

你的供应商，你的密钥，你的电脑。

接入火山方舟 Seedance、fal、Replicate 或任何 OpenAI 兼容的视频服务，也可以用 JSON manifest 导入自定义供应商。凭据只保存在本机设置里，Agent 只能看到是否已配置。

  • 供应商 manifest，无需改代码
  • FFmpeg 与深度模型显式准备，按哈希固定
  • Go 服务只监听回环地址

计划、审片、剪辑

模型提议，你来决定。

01

先看计划

在付费之前，生成计划会显示最终提示词、真实模型参数和每条参考的职责：instruction、identity、composition、motion 或 exclude。

02

六项检查，你说了算

方向、动作、身份、空间连续、意外切镜、形变与品牌。只有你逐项标记并写下观察，候选才会被批准。被拒绝的候选留在工程里。

03

只换一镜，其余不动

剪辑计划保存 2 到 16 镜、入出点、输出规格和一条音轨。换掉一镜，其他镜头原样保留。渲染生成新成片，旧成片仍在。

影片

三十秒。每一帧都由代码绘制。

发布影片与产品共用同一套设计体系。没有素材库、没有生成镜头、没有截图：每一个界面元素都是逐帧渲染的真实状态。

分镜与源码在 GitHub

开始使用

构建它，打开一个目录，连接你的 Agent。

0.4.0 正在开发中。从源码构建需要 Bun 1.3.14+、Go 1.26+ 与 Node.js 22+；运行打包后的插件只需 Node.js 22+。

从源码运行

git clone https://github.com/junjamrk/OpenCinema.git
cd OpenCinema
bun install --frozen-lockfile
bun run build
bun start

打开 http://127.0.0.1:47920，选择任意目录作为工程。

连接 Claude Code

claude --plugin-dir ./build/openCinema
# 然后
/opencinema:opencinema

Codex：codex plugin add opencinema@openCinemaStandalone。任何 MCP 客户端都可以从设置面板复制连接配置。

开源

在公开中构建。

MIT 许可。Go 服务、React 画布、框架无关的编辑会话和节点 SDK，都在同一个仓库里。欢迎 Issue、Pull Request 和节点插件。

写一个节点

节点是一个导出插件定义、用 Zod 注册工具的包。你的界面和 Agent 调用的是同一个实现。

接入一个供应商

说同一种协议的服务只需要一个 JSON manifest。没有映射的参考会被明确拒绝，而不是悄悄丢掉。

打磨工具面

每个工具都有实时 Schema、输出校验与标注。错误自带机器码和恢复动作。

提一个 Issue

  • 0.4.0 正在开发中，尚未发布。
  • AI 生成使用你配置的供应商，可能计费。任何宿主订阅都不包含视频模型。
  • 预演、白模与深度是参考。运动分析追踪姿态与 2D 相机运动，不是 3D 解算。
  • 审片是由人做出并记录的决定。
