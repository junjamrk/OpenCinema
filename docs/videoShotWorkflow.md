# 视频镜头计划与审片

视频生成的 `completed` 表示任务已产生并保存媒体。当前输出可以预览，但它仍是候选；创作审片独立记录为 `pending`、`approved` 或 `rejected`。这些状态不代表模型自动判断过质量。

## 生成前

1. 用 `getReferences` 读取真实连线和顺序，按需要调用 `setReferenceRoles`。旧节点默认仍使用全部原参考，不会静默删掉全片文本或图片。
2. 用 `setShotBrief` 为本镜保存一个主要动作，将 `subjectDirection`（相对地面和车身的运动）、`screenDirection`（在画面中的方向）、`cameraMotion`（摄影机运动）分开。`continuousShot: true` 请求一个连续镜头，仍须审查模型是否遵循。
3. 调用 `getGenerationPlan`。它返回最终提示词、字符数、实际模型目录参数、每条参考的职责、是否有效、媒体序号和源文件快照版本；不会付费生成。专项模型与宿主使用同一提示词及参考过滤。
4. 确认后才调用 `generateVideo`。未使用的全片外景文本可显式设置为 `exclude`；主体图可设置为 `identity`，让提示词只要求外观、沿用本镜构图。

职责是应用侧的创作语义：`instruction` 用于文本，`identity` 用于图片，`composition` 用于图片或视频，`motion` 用于视频，`exclude` 保留连线但不发送。它们不会变成供应商未声明的控制参数。方舟普通 `reference_video` 是软参考；当前没有声明专用 Depth Control 或精确运动锁定。身份图的职责说明也不是供应商保证；首帧模式仍会把所选图片作为首帧使用。

`{{ref N}}` 以连线顺序索引，并编译为实际的「图片 1／视频 1／文本参考 N」语义。排除或不存在的引用会在提交前报错；`getGenerationPlan.references.mediaIndex` 可核对过滤后的实际媒体序号。

生成节点高级区的「镜头计划」使用同一工具；参考缩略图弹层可修改「生成职责」。底部输入继续承担与 Agent 对话、发起创作的入口，不在节点重复增加常驻提示词表单。

## 生成后

1. 播放实际视频，观察需要采用的区间；可对照参考，查看是否倒行、动作成立、主体变换、空间跳变、自发切镜及形变／品牌问题。
2. 调用 `getVideoReview` 取得当前真实路径、`sourceRevision`、画面时长和既有审片记录。
3. 调用 `reviewVideo` 明确 `start/end`、`checks`、`notes` 和 `status`。只有方向、动作、身份、空间连续、意外切镜、形变与品牌六项都为 `pass` 或 `notApplicable` 才可标记 `approved`；操作者必须提供实际观察记录。`rejected` 保留原片。
4. `composeVideo` 只消费同一源版本且落在通过范围内的可追溯生成片段。未审、拒收、范围越界或源版本变化会拒绝合成；模型生成成功不能跳过这一判断。

高级区「审阅候选」和普通视频的媒体编辑区「审阅视频」调用同一工具。裁掉有问题的段落后，应播放保留的范围再审；这不意味着原生成问题已经被模型修复。

## 保存剪辑计划与局部换镜

新执行的 `composeVideo` 会在结果视频节点同时保存 `videoEditPlan`。它保留按顺序使用的 `clips`、源文件版本、实际整帧入出点、分辨率、帧率和可选音轨，并绑定渲染产物与版本。旧成片没有这些数据时返回无计划，不按来源连线猜测原剪辑。

1. `getVideoEditPlan` 返回独立 `planRevision`、完整 `plan`、上次渲染记录和各输入的当前可读／版本状态，并返回逐镜标签、源节点、整帧入出点、成片时段、源时长、最新审片、阻塞原因、总帧数／时长及 `canRender`。`current` 只表示当前文件对应此计划，不能代替创作审片。
2. `setVideoEditPlan` 以 `expectedPlanRevision` 完整保存计划。局部换一镜时读取全部计划，只修改相应 `clips` 项及其源版本、采用范围，其余镜头保留。没有计划时修订为 0，保存后递增；保存不会更新视频文件。
3. `renderVideoEditPlan` 携带保存后的 `expectedPlanRevision`，复用原组合链路创建新成片节点，原视频保留。编码前和采用前均核对计划修订与内容、原输出及其文件版本、各输入版本和已审范围。新结果保存实际渲染的整帧计划。

计划内容为 `{version:1, clips, resolution, fps, audio?}`；每条 `clips` 使用 `{path,sourceRevision,start?,end?,label?}`；label 保留镜头身份，替换素材不会丢掉原镜头名称。音轨仍是已有的单条混合／替换能力，不把保存计划当成已实现多轨声音编辑。

手工入口位于视频的「媒体编辑 → 剪辑计划」。弹层显示全片时长和逐镜成片时段、审片状态及具体阻塞，可定位源节点、调整入出点／镜头顺序，并从当前画布已有视频替换单镜。替换保留原入出点及其余镜头、规格和音轨；候选短于原出点时明确阻塞，不静默缩短成片。Agent 操作同一持久计划。修改后需先保存再渲染，界面明确区分计划已修改与视频已产生。普通 `composeVideo` 的首源保护继续保留；只有显式渲染当前保存计划才能从成片本身重新编排原始分镜。渲染结果未知时查询原 `getOperation`，不重复派发。

## 固定白模参考与完整影片返修

1. 先在 Blockout 修订场景、Take 和镜头，再导出所选镜头 RGB／Depth。修改项目会清空当前发布输出；新单镜导出会整组替换 RGB／Depth／Normal／manifest，未导出的旧层不再挂在当前输出上，历史文件保留。整场 Animatic 单独保留。
2. 手工在 Blockout「导出」点「固定为本镜参考节点」，或 Agent 调用 `freezeBlockoutReference`，携带当前资源 expectedRevision、sceneId、shotId 和 rgb/depth 层。工具核对项目、镜头、manifest 的精确层路径和当前媒体版本后，一次建立独立普通视频节点；每层 referenceSnapshot 保存资源、镜头、层、manifest 与媒体版本，不改既有连线、不覆盖媒体。它绑定固定时版本，不证明发布后到固定前从未被外部改写。
3. 将本镜固定 RGB 接入对应生成候选的 motion，将身份图设为 identity；Depth 可接入并默认 exclude，用计划明确选择实际发送哪一层。不能把 RGB 与 Depth 同时堆成多个动作参考来假定控制更强。普通 Seedance reference_video 仍是软参考；没有专用 Depth Control 的硬约束。02轮胎／04手部粗模未达可用精度时使用对应关键帧，不拿粗模冒充精细动作控制。
4. `getGenerationPlan` 返回 documentRevision 与实际参考路径／版本／requestSlot。读取期间修订变化会拒绝混合计划；专项模型和宿主提交前均再次核参考版本。media 中的 controlType 元数据不会再导致 Depth 漏出计划／版本冻结。提交前校验与后端读取之间仍不是原子文件版本协议。
5. 先看完整预演的叙事和连续性，再逐镜生成、实片审阅、只换有问题的镜头。保存后刷新全片预检，只有全体技术与已审采用区间可用时才允许渲染新成片；`canRender` 不自动判断镜间轴线、车距、身份或商业质量。

替换列表只排除输出显式带非空 controlType 的控制片；旧手工视频／重新导入且丢失元数据的深度片仍作为普通视频出现，不按名称或黑白外观猜测。通用 compose 仍可用于独立编辑这些视频。

## 保护与范围

- `generation.request` 保存真正有效的提示词、参数、工作区媒体路径和创作职责。`creativeFingerprint` 检测提示词、模型配置、计划与连线变化；`referenceVersions` 绑定工作区文件快照版本，阻止同路径替换后的旧结果自动覆盖。它们不是完整素材 SHA 冻结，也不保证模型可确定性复现。供应商自己的参考 SHA 与任务回执另行保留。
- 生成前将旧产物身份迁移到 `videoSourceHistory`，新产物继续追加；每个源版本保留自己的审片，选择历史、复制节点不会丢掉这些来源或旧版本结论。普通导入的自愿审片也保存为明确的 `imported` 来源，不伪称模型生成。截取、变速、分离和合成保留父来源，新的视频文件默认重新审片，不自动继承创作通过。
- 审片读取与合成均采用同画布同源版本的最新逻辑修订，避免复制节点显示旧通过、合成却被新拒收阻塞的恢复死循环。同修订冲突时拒收优先；新显式复审可以用更高修订改为通过，不依赖墙钟排序。合成开始及产物采用前重新核对版本、范围和结论，避免编码期间的变更静默进入结果。
- 审片门槛覆盖同画布节点历史与衍生链中可追溯的生成源。普通独立导入不强制审片。将文件复制到新路径并作为全新导入、同时丢弃原节点来源时，不会凭内容相似度重新识别其生成身份；当前没有全工程文件来源注册表。产品门槛用于防止制作流程中的误采用，不能称为覆盖任何导入副本的来源安全边界。
